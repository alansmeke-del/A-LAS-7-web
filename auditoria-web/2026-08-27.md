- El botón/CTA premium y el popup de promo apuntan al Payment Link de Stripe correcto: `https://buy.stripe.com/14AcN50xF8OM2OW4SsafS01` (index.html, líneas 361, 391, 515).

- **Hallazgo de seguridad (nuevo, no reportado antes):** el bearer token de MailerLite (JWT completo) y el secreto compartido `X-ALAS7-Secret` (`alas7secret2026`) están **hardcodeados en texto plano dentro del `<script>` público** de `index.html` (líneas 393 y 395). El JWT decodificado muestra `exp` en el año ~2126 (prácticamente no expira) y `scopes: []` (alcance no restringido visible). Cualquiera puede hacer "ver código fuente" y extraer ambas credenciales, lo que permitiría:
  - Generar códigos de promoción arbitrarios llamando directo a `/generate-promo` sin pasar por el sitio.
  - Usar el bearer token para llamar la API de MailerLite (o el proxy) directamente, potencialmente para inscribir/enumerar suscriptores según el alcance real del token.
  - Esto es un riesgo activo de abuso de dinero/datos, no solo un detalle de estilo.

**Problemas encontrados:**
1. (Alto/seguridad) Bearer token de MailerLite y secreto `X-ALAS7-Secret` expuestos en texto plano en el JS público de `index.html`.
2. (Bloqueante para esta auditoría, no del sitio) Sandbox sin salida de red hacia alas7.com/Stripe/Railway — impidió confirmar en vivo el estado 200, el Stripe Payment Link y los endpoints de promo/subscribe.
3. (Menor) Clave `vita_promo_seen` con el nombre de marca anterior.
4. (Menor) Íconos sociales del footer sin URL real (`href="#"`).

**Recomendación:** (qué se debería arreglar, PERO NO SE ARREGLÓ)
- Prioridad alta: mover el bearer token de MailerLite y el secreto de promo fuera del cliente — que el navegador llame al proxy de Railway sin credenciales embebidas, y que el proxy adjunte el bearer/secret del lado del servidor. Rotar ambas credenciales una vez movidas, ya que las actuales deben considerarse comprometidas (visibles públicamente desde hace varios commits).
- Verificar desde una máquina con salida de red normal que alas7.com responde 200 y que los tres endpoints (Stripe, /generate-promo, /subscribe) responden como se espera.
- Opcional: renombrar la llave `vita_promo_seen` a algo con la marca actual, y actualizar o quitar los íconos sociales placeholder.
