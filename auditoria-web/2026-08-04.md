**Problemas encontrados:**
1. **(Seguridad, nuevo) Secretos hardcodeados en el JS del cliente.** El `index.html` expone en texto plano y visible vía "ver código fuente" tanto el JWT `Bearer` completo usado para `/subscribe` como el secreto `X-ALAS7-Secret` (`alas7secret2026`) usado para `/generate-promo`. Cualquier visitante puede copiar estas credenciales y llamar los endpoints directamente — generar códigos promo ilimitados o intentar abusar del endpoint de suscripción sin pasar por la UI. No rompe la conversión hoy, pero es un vector de abuso explotable.
2. **(Menor) Links de redes sociales rotos.** Los 3 íconos del footer (Instagram, X, LinkedIn) apuntan a `href="#"` sin URL real — no llevan a ningún perfil.
3. **(Informativo) Manejo de error silencioso en el popup de promo.** Si `/generate-promo` falla, `showPromo()` cae a un código fijo `'ALAS7-2026'` sin loggear ni avisar; si el endpoint cae, todos los visitantes reciben el mismo código genérico sin que nadie se entere.
4. **(Informativo) No verificable:** salud HTTP en vivo del sitio, del endpoint de promo y de Stripe — bloqueado por la política de red de este entorno de auditoría (ver detalle arriba). No representa evidencia de que algo esté caído, solo que no se pudo confirmar directamente esta corrida.

Sin hallazgos: CNAME correcto (`alas7.com`), sintaxis del JS válida (`node --check` sin errores), no se encontraron dominios rotos tipo `alas7.mx`, y los recursos referenciados (`aviso-de-privacidad.html`, `terminos.html`, `assets/logo7-v2.png`) existen en el repo.

**Recomendación:** (PERO NO LO ARREGLES — solo aviso)
- Mover el JWT y el secreto de promo fuera del JS del cliente (proxy server-side que no exponga credenciales, o rotar y limitar el alcance de esas credenciales).
- Confirmar manualmente desde fuera de este entorno que `alas7.com`, el endpoint de promo y el link de Stripe responden 200/OK, ya que esta corrida no pudo verificarlo por restricciones de red del sandbox.
- Completar o quitar los links de redes sociales del footer.
- Opcional: loggear (aunque sea a un servicio externo) cuando `/generate-promo` falla y se usa el código de respaldo, para detectar caídas del endpoint sin depender de que un usuario reporte el problema.
