**Problemas encontrados:**
1. **(Grave — dinero) Secretos de pago/promo expuestos en el HTML público.** En `index.html` (líneas ~393-395), el script inline trae en texto plano:
   - El Bearer token JWT completo de la API de MailerLite (`const BEARER = 'eyJ0eXAi...'`).
   - El secreto compartido del endpoint de promociones (`const SECRET = 'alas7secret2026'`, usado como header `X-ALAS7-Secret`).
   Cualquier visitante puede ver el código fuente y extraer ambos valores. Con el secreto de promo, alguien podría llamar directo a `/generate-promo` fuera del flujo del sitio y generar códigos de descuento ilimitados, sin pasar por el timer de 5 minutos ni la lógica de "solo nuevos lectores" — esto afecta ingresos directamente. Con el Bearer de MailerLite expuesto, alguien podría llamar otros endpoints de esa API con los mismos permisos del token (alcance exacto sin verificar, pero el token es de larga vida — `exp` codificado es del año 2126).
2. **(Menor) Manejo de error silencioso en el popup de promo.** En `showPromo()`, si `fetch(API + '/generate-promo')` falla, el catch asigna en silencio el código genérico `'ALAS7-2026'` sin avisar al usuario ni registrar el fallo. Si el endpoint está caído, todos los visitantes reciben el mismo código fijo sin que nadie se entere de que el servicio de promos falló.
3. **(Cosmético) Resto de marca anterior.** La clave de `sessionStorage` sigue llamándose `'vita_promo_seen'` (marca previa "Vita"), en vez de algo con el nombre actual "A LAS 7". No rompe nada, pero es un residuo del rebrand.
4. **(Menor) Íconos sociales sin destino.** Los enlaces de Instagram, X y LinkedIn en el footer (`href="#"`) no tienen URL real ni manejador de JS — son decorativos. Esperable si aún no existen esas cuentas, pero vale la pena confirmarlo.

Verificado y sin hallazgos: sintaxis del JS válida (`node --check` limpio), `CNAME` correcto (`alas7.com`, no `vitanews` ni otro dominio), sin referencias a dominios inexistentes tipo `alas7.mx`, imagen `assets/logo7-v2.png` presente en el repo, enlaces internos entre `index.html`, `aviso-de-privacidad.html` y `terminos.html` consistentes.

**Recomendación:** (PERO NO LO ARREGLES)
- Prioridad 1: mover la llamada a `/generate-promo` y `/subscribe` detrás de un backend/proxy que agregue el secreto y el Bearer del lado del servidor, para que nunca viajen en el HTML público. Como mitigación rápida sin tocar el front: rotar el `X-ALAS7-Secret` y el Bearer de MailerLite periódicamente, y poner rate-limiting/validación de origen en el backend de Railway para `/generate-promo`.
- Prioridad 2: que el catch de `showPromo()` reporte el fallo (aunque sea a un logging simple) en vez de fallar en silencio con el código genérico.
- Opcional: renombrar la clave de `sessionStorage` y decidir si los íconos sociales deben apuntar a cuentas reales o quitarse mientras no existan.
- Nota operativa: en la próxima corrida conviene confirmar el estado HTTP real de alas7.com desde un entorno con salida de red completa, ya que esta corrida no pudo verificarlo directamente.
