**Problemas encontrados:**
1. **[CRÍTICO] Credenciales en texto plano en el JS público.** En `index.html:395` hay un Bearer token JWT completo de MailerLite embebido en el `<script>` del lado del cliente (visible con "ver código fuente" por cualquier visitante). Decodificado: `scopes: []` (sin restricción de alcance) y `exp` en el año ~2126 — es decir, es un token de API personal, de acceso amplio y esencialmente sin expiración, expuesto públicamente. Cualquiera puede copiarlo y llamar directamente a la API de MailerLite (agregar/leer suscriptores, o más, según lo que permita esa cuenta) sin pasar por el proxy de Railway.
2. **[ALTO] El secreto del endpoint de promociones también está expuesto.** `index.html:393` define `SECRET = 'alas7secret2026'` y se envía tal cual como header `X-ALAS7-Secret` (index.html:508). Al estar en el JS público, deja de funcionar como secreto: cualquiera puede leerlo y generar códigos promo directamente contra el endpoint de Railway, sin pasar por la landing.
3. **[MEDIO] Fallback silencioso en el popup de promo.** Si la llamada a `/generate-promo` falla (`index.html:506-513`), el catch asigna en silencio el código fijo `ALAS7-2026` y sigue mostrando el popup como si nada, sin avisar al usuario ni registrar el error. Si Stripe no reconoce ese código fijo como promo code válido, el usuario ve un cupón que en checkout no aplica descuento — mala experiencia y pérdida de conversión sin que nadie se entere de que el endpoint está fallando.
4. **[BAJO / esperado] Iconos sociales sin URL real.** Los enlaces de Instagram, X y LinkedIn en el footer (`index.html:321-323`) son `href="#"` puros sin JS asociado — parecen placeholders pendientes de completar, no un bug de código, pero rompen la promesa visual de "síguenos".
