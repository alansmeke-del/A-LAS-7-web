**Problemas encontrados:**
1. **[CRÍTICO — seguridad] Credenciales expuestas en el HTML público.**
   `index.html` (líneas ~393–395, variables `SECRET` y `BEARER` dentro del
   `<script>`) contiene en texto plano, visible para cualquier visitante que
   abra "ver código fuente":
   - Un Bearer token JWT completo de la API de MailerLite, usado en el header
     `Authorization` de la llamada a `/subscribe`. El token decodifica a
     `exp` = año 2126 (prácticamente sin expiración) y `scopes: []`.
   - El secreto `alas7secret2026`, enviado como header `X-ALAS7-Secret` al
     endpoint `/generate-promo`.
   Cualquiera puede copiar estas credenciales del código fuente y llamar a
   la API de MailerLite o al endpoint de promos directamente, sin pasar por
   el sitio. Esto no es un problema de conversión, pero sí de seguridad de
   cuenta/datos. No se tocó nada — solo se documenta.
2. **[Menor] Manejo de errores silencioso en el JS.** Los dos `catch` de
   `fetch` (formulario gratis ~línea 457, popup de promo ~línea 511) no
   registran nada en consola cuando el backend falla — solo muestran un
   fallback visual al usuario (mensaje de error genérico o código promo
   estático `ALAS7-2026`). Funciona para el usuario, pero si Railway cae no
   queda ningún rastro fácil de detectar desde el navegador.
3. **[Cosmético] Enlaces sociales sin URL real.** Los íconos de Instagram, X
   y LinkedIn en el footer (`href="#"`, líneas ~321–323) no llevan a ninguna
   parte. No afecta conversión ni pago.

**Sin hallazgos en:** sintaxis del JS (validado con `node --check` sobre el
bloque `<script>`, sin errores), CNAME (dice `alas7.com`, correcto), y no se
encontraron referencias a dominios incorrectos (`alas7.mx`, `vitanews`, etc.)
en el HTML.
