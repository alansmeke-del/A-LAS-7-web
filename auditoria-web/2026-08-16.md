**Problemas encontrados:**
1. **Token de MailerLite y secreto de promo expuestos en texto plano en el JS del cliente** (index.html líneas 393 y 395): la constante `BEARER` contiene un JWT completo de la API de MailerLite y `SECRET` (`alas7secret2026`) es el header `X-ALAS7-Secret` que protege `/generate-promo`. Ambos son visibles con "ver código fuente" por cualquier visitante. El JWT decodificado tiene un `exp` extremadamente lejano (~año 2126), es decir, no vence. Cualquiera puede copiar este token y llamar directamente a la API de MailerLite o generar códigos promo sin pasar por el sitio.
2. **Fallo silencioso en `/generate-promo`** (index.html línea 506-513): si el endpoint de Railway falla o no responde, el `catch` no registra ni reporta el error — simplemente sustituye el código por el literal `'ALAS7-2026'` y continúa como si nada. El usuario no nota nada raro, pero Alan tampoco se enteraría si el backend de promos empieza a fallar de forma sostenida (queda enmascarado por el fallback).
3. **Enlaces sociales muertos** (index.html líneas 321-323): los íconos de Instagram, X y LinkedIn en el footer usan `href="#"` sin ningún listener de JS asociado (a diferencia de los `href="#"` con clase `js-open-free`, que sí están cableados a la apertura del modal). Son enlaces decorativos que no llevan a ningún lado.
4. **Resto menor:** la constante `SESSION_KEY = 'vita_promo_seen'` (línea 396) conserva el nombre "vita" de una marca/proyecto anterior — no rompe nada, pero es un rastro de naming inconsistente con "alas7".
