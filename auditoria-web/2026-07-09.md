**Problemas encontrados:**
1. **(Media) Token Bearer de MailerLite hardcodeado y expuesto en el JS del cliente** (`index.html`, línea ~10, variable `BEARER`). Es un JWT visible en el código fuente público de la página (cualquiera puede verlo con "ver código fuente"). El payload decodificado muestra `exp` con una fecha muy lejana (prácticamente no expira) y `scopes: []`. Un token de API expuesto públicamente y de larga vida es un riesgo — alguien podría extraerlo y usarlo para llamar directamente a la API de MailerLite fuera del flujo previsto del sitio.
2. **(Baja) Manejo de error silencioso en `generate-promo`** (`index.html`, función `showPromo`, líneas ~121-128): si el `fetch` a `/generate-promo` falla (endpoint caído, error de red, CORS, etc.), el `catch` no registra nada (ni `console.error` ni aviso al usuario) — simplemente cae a un código estático `'ALAS7-2026'`. Esto es intencional como fallback de UX, pero significa que un fallo real del endpoint de promo nunca se notaría por ningún canal (ni consola, ni logs, ni al usuario) — solo se detectaría por auditoría manual o quejas de usuarios sobre códigos genéricos.
3. **(Cosmético) Enlaces sociales sin URL real**: los íconos de Instagram, X y LinkedIn en el footer (`index.html`, líneas 321-323) usan `href="#"` — no llevan a ningún perfil real. Esto parece un placeholder pendiente de completar (no es un enlace roto ocasionado por un bug, sino contenido incompleto).
4. Los otros `href="#"` en el sitio (líneas 66, 308, botones "Gratis"/"Suscríbete gratis") son intencionales — abren el modal de suscripción vía JS (`js-open-free`), no son enlaces rotos.
