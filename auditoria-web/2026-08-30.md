**Problemas encontrados:**

3. El fallo del endpoint `/generate-promo` es silencioso — no hay alerta si el servicio de promos se cae.
4. Cosmético: clave `vita_promo_seen` en sessionStorage, remanente de la marca anterior.
5. Limitación de esta corrida: no se pudo confirmar en vivo el status HTTP de alas7.com, Stripe ni el proxy de Railway por bloqueo de egress del entorno del auditor.

**Recomendación:** (qué se debería arreglar, PERO NO LO ARREGLES)
- Prioridad alta: mover el Bearer token y el secreto `X-ALAS7-Secret` fuera del JS del cliente — deben vivir solo en el backend (el proxy de Railway), nunca en HTML público. Si no se puede evitar por completo, rotar ambas credenciales cuanto antes, ya que quedaron expuestas en el HTML de producción.
- Añadir manejo de error visible (log a un servicio de monitoreo, o al menos `console.error`) en el `catch` de `showPromo()` para detectar caídas del endpoint de promos.
- Reemplazar los `href="#"` del footer con las URLs reales de Instagram/X/LinkedIn, o quitar los íconos si aún no existen esas cuentas.
- Opcional/cosmético: renombrar la clave `vita_promo_seen` a algo con el prefijo `alas7_`.
- Configurar un monitor de uptime externo para alas7.com, Stripe y el proxy de Railway, ya que este auditor automatizado no tiene salida de red hacia esos dominios y no puede confirmar su disponibilidad en cada corrida.
